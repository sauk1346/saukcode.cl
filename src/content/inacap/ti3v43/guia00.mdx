# Guía Resumen: Ingeniería de Software

## 1. TEORÍA GENERAL DE SISTEMAS

### Conceptos Fundamentales

**¿Qué es un Sistema?**
Un sistema es un conjunto de elementos interrelacionados que trabajan hacia un objetivo común. En software: componentes, módulos, interfaces que funcionan coordinadamente.

**Principios Clave:**

| Principio | Descripción |
| --- | --- |
| **Holismo** | *El todo es más que la suma de sus partes* |
| **Sinergia** | *El efecto conjunto supera los efectos individuales* |
| **Emergencia** | *Propiedades que surgen solo de la interacción entre componentes* |

### Tipos de Sistemas

| Tipo | Descripción |
| --- | --- |
| **Sistemas Abiertos** | :li[Intercambian energía, materia e información con el entorno] :li[Se adaptan y evolucionan] :li[**Ej:** aplicaciones web, sistemas distribuidos] |
| **Sistemas Cerrados** | :li[No intercambian con el entorno] :li[Más predictibles pero menos adaptables] :li[**Ej:** sistemas embebidos específicos] |

### Propiedades Sistémicas

| Tipo | Descripción |
| --- | --- |
| **Retroalimentación** | :li[Salidas del sistema que se convierten en entradas] :li[Permite autorregulación y mejora continua] :li[Fundamental en desarrollo iterativo] |
| **Homeostasis** | :li[Capacidad de mantener equilibrio interno] :li[Adaptación a cambios manteniendo estabilidad] :li[Importante para sistemas en producción] |
| **Entropía** | :li[Tendencia natural hacia el desorden] :li[**En software:** degradación del código, acumulación de deuda técnica] :li[Se combate con mantenimiento y refactoring] |
| **Equifinidad** | :li[Múltiples caminos pueden llevar al mismo resultado] :li[Flexibilidad en metodologías y arquitecturaa] |
| **Jerarquía** | :li[Organización por niveles de abstracción] :li[Desde componentes hasta sistemas completos] |
| **Fronteras** | :li[Límites que separan el sistema de su entorno] :li[Definen interfaces y puntos de integración] |

### Aplicaciones en Software

| Principio | Descripción |
| --- | --- |
| **Arquitectura** | Sistemas como jerarquías de subsistemas |
| **Desarrollo** | Equipos como sistemas socio-técnicos |
| **Mantenimiento** | Sistemas adaptativos que evolucionan |
| **Integración** | Sistema de sistemas interconectados |

## 2. MODELOS DE CICLOS DE VIDA

### Modelo en Cascada

| Concepto | Descripción |
| --- | --- |
| **Características** | :li[Desarrollo secuencial y lineal] :li[Fase bien definidas sin solpamiento] :li[Documentación extensa entre fases] :li[Difícil retroceso a fases anteriores] |
| **Fases** | :li[Análisis de requisitos] :li[Diseño del sistema] :li[Implementación] :li[Pruebas] :li[Despliegue] :li[Mantenimiento] |
| **Ventajas** | :li[Estructura clara y predecible] :li[Fácil gestión y seguimiento] :li[Documentación completa] :li[Adecuado para proyecto con requisitos estables] |
| **Desventajas** | :li[Inflexible ante cambios] :li[Detección tardía de problemas] :li[No hay entregas tempranas] :li[Riesgo alto en proyectos complejos] |

### Modelo en V (V-Model)

| Concepto | Descripción |
| --- | --- |
| **Características** | :li[Extensión del modelo en cascada] :li[Cada fase de desarrollo tiene una fase de prueba correspondiente] :li[Enfoque tempano en verificación y validación] |
| **Estructura** | :li[Lado izquiedo: Especificación y diseño] :li[Lado derecho: Pruebas y validación] :li[Conexiones entre fases relacionadas] |
| **Ventajas** | :li[Énfasis temprano de testing] :li[Mejor control de calidad] :li[Clara trazabilidad entre requisitos y pruebas] |

### Modelo en Espiral

| Concepto | Descripción |
| --- | --- |
| **Características** | :li[Combina desarrollo iterativo con evaluación sistemática de riesgos] :li[Ciclos repetitivos en espiral] :li[Cada iteración pasa por las mismas fases] |
| **Fases por Iteración** | :li[**Planificación:** Objetivos, alternativas, restricciones] :li[**Análisis de Riesgos:** Identificación y resolución de riesgos] :li[**Ingeniería:** Desarrollo del producto] :li[**Evaluación:** Revisión con el cliente] |
| **Ventajas** | :li[Gestión proactiva de riesgos] :li[Flexibilidad y adaptabilidad] :li[Entrega incremental] :li[Adecuado para proyectos grandes y complejos] |

### Desarrollo Iterativo e Incremental

| Tipo | Descripción |
| --- | --- |
| **Incremental** | :li[El producto se contruye por partes (incrementos)] :li[Cada incremento añade funcionalidad] :li[Entregas periódicas de software funcional] |
| **Iterativo** | :li[Refinamiento continuo a través de ciclos] :li[Cada iteración mejora y extiende versiones anteriores] :li[Permite incorporar feedback frecuente] |

## 3. NORMAS ISO

### ISO/IEC 12207 - Procesos del Ciclo de Vida del Software

**Objetivo:**
Establecer un marco común para los procesos del ciclo de vida del software desde la concepción hasta el retiro.

#### Clasificación de Procesos

| Procesos | Descripción |
| --- | --- |
| **Procesos Principales** | :li[**Adquisición:** Actividades del cliente que adquiere software] :li[**Suministro:** Actividades del proveedor que suministra software] :li[**Desarrollo:** Actividades para crear y mantener software] :li[**Operación:** Uso operacional del software] :li[**Mantenimiento:** Modificación del software después de su entrega] |
| **Procesos de Soporte** | :li[Documentación] :li[Gestión de configuración] :li[Aseguramiento de calidad] :li[Verificación] :li[Validación] :li[Revisión conjunta] :li[Auditoría] :li[Resolución de problemas] |
| **Procesos Organizacionales** | :li[Gestión] :li[Infraestructura] :li[Mejora] :li[Formación] |

#### Características de los Procesos

**Proceso de Desarrollo incluye:**
- Análisis de requisitos del sistema
- Diseño de la arquitectura del sistema
- Análisis de requisitos del software
- Diseño de la arquitectura del software
- Diseño detallado del software
- Codificación y testing
- Integración
- Testing de calificación

**Proceso de Mantenimiento:**
- Mantenimiento correctivo (corrección de defectos)
- Mantenimiento adaptativo (adaptación a cambios del entorno)
- Mantenimiento perfectivo (mejora de rendimiento o mantenibilidad)
- Mantenimiento preventivo (prevención de futuros problemas)

### ISO/IEC 25000 (SQuaRE) - Calidad del Producto Software

**Objetivo:**
Proporcionar un marco para la especificación y evaluación de la calidad del producto software y datos.

**Reemplaza a:**
- ISO/IEC 9126 (modelo de calidad)
- ISO/IEC 14598 (evaluación de productos software)

#### División de la Serie 25000

| División | Descripción | Ejemplos |
| --- | --- | --- |
| **ISO/IEC 2500n** | **Gestión de Calidad** | :li[**25000:** Guía general y vocabulario] :li[**25001:** Planificación y gestión] |
| **ISO/IEC 2501n** | **Modelo de Calidad** | :li[**25010:** Modelo de calidad del producto software] :li[**25012:** Modelo de calidad de datos] |
| **ISO/IEC 2502n** | **Medición de Calidad** | :li[**25020:** Guía de medición] :li[**25023:** Medición de calidad del producto software] |
| **ISO/IEC 2503n** | **Requisitos de Calidad** | :li[**25030:** Requisitos de calidad] |
| **ISO/IEC 2504n** | **Evaluación de Calidad** | :li[**25040:** Proceso de evaluación] :li[**25041:** Guía de evaluación] |

#### Modelo de Calidad ISO/IEC 25010

| Características de Calidad | Descripción |
| --- | --- |
| **Funcionalidad** | :li[Completitud funcional] :li[Corrección funcional] :li[Pertinencia funcional] |
| **Eficiencia de desempeño** | :li[Comportamiento temporal] :li[Utilización de recursos] :li[Capacidad] |
| **Compatibilidad** | :li[Coexistencia] :li[Interoperabilidad] |
| **Usabilidad** | :li[Reconocimiento de ideoneidad] :li[Capacidad de aprendizaje] :li[Capacidad de operación] :li[Protección contra errores de usuario] :li[Estética de la interfaz de usuario] :li[Accesibilidad] |
| **Fiabilidad** | :li[Madurez] :li[Disponibilidad] :li[Tolerancia a fallos] :li[Capacidad de recuperación] |
| **Seguridad** | :li[Confidencialidad] :li[Integridad] :li[No repudio] :li[Responsabilidad] :li[Autenticidad] |
| **Mantenibilidad** | :li[Modularidad] :li[Reusabilidad] :li[Analizabilidad] :li[Modificabilidad] :li[Capacidad de testing] |
| **Portabilidad** | :li[Adaptabilidad] :li[Facilidad de instalación] :li[Capacidad de reemplazo] |

#### Aplicación Práctica de las Normas

| Aplicación | Descripción |
| --- | --- |
| **En Proyectos de Desarrollo** | :li[Selección de procesos apropiados según ISO 12207] :li[Definición de requisitos de calidad según ISO 25030] :li[Evaluación del producto según ISO 25040] |
| **En Gestión de Calidad** | :li[Establecimiento de métricas de calidad] :li[Procesos de aseguramiento de calidad] :li[Evaluación objetiva de productos software] |
| **En mejora de Procesos** | :li[Identificación de gaps en procesos actuales] :li[Implementación de mejores prácticas] :li[Medición y mejora continua] |

## 4. RESUMEN EJECUTIVO

| Concepto | Descripción |
| --- | --- |
| **Teoría de Sistemas** | Los sistemas de software son entidades complejas con propiedades emergentes que requieren un enfoque holístico para su comprensión y gestión. |
| **Modelos de Ciclos de Vida** | La elección del modelo depende de factores como estabilidad de requisitos, tolerancia al riesgo, necesidad de entregas tempranas y capacidad de adaptación al cambio. |
| **Normas ISO** | Proporcionan marcos estandarizados para procesos (ISO 12207) y calidad (ISO 25000), facilitando la mejora continua y la comparabilidad entre organizaciones. |
| **Integración de Conceptos** | La efectividad en **Ingeniería de Software** surge de la aplicación coordinada de principios sistémicos, modelos de desarrollo apropiados y estándares de calidad reconocidos. |
