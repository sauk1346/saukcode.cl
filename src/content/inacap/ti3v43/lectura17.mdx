# Desarrollo de prototipos según requisitos de proyecto

El desarrollo de prototipos es una etapa elemental en la creación de software. Permite validar ideas, entender los requerimientos y ajustar funcionalidades antes de implementar un sistema completo.

## 1. ¿Qué es un prototipo?
Es una versión inicial o parcial de un sistema de software que sirve para:

- Visualizar cómo funcionará el producto final.
- Identificar posibles problemas en etapas tempranas.
- Validar y refinar los requerimientos junto con los interesados.

## 2. Tipos de prototipos

### Prototipo de baja fidelidad
Este tipo de prototipo es una representación simple y preliminar del producto final. No incluye detalles específicos ni funcionalidades complejas, sino que se enfoca en la estructura y el flujo general del sistema.

| Baja Fidelidad | Descripción |
| --- | --- |
| **Características** | :li[**Bocetos:** Son dibujos a mano alzada que muestran la disposición básica de los elementos en la interfaz] :li[**Wireframes:** Son diagramas que representan la estructura de las páginas o pantallas, indicando la ubicación de los elementos principales como botones, menús y campos de entrada] |
| **Ventajas** | :li[**Rápido y económico:** Se pueden crear rápidamente y con pocos recursos] :li[**Facilita la comunicación:** Ayuda a los equipos a visualizar y discutir ideas sin invertir mucho tiempo en detalles] :li[**Flexibilidad:** Es fácil de modificar y ajustar según la retroalimentación recibida] :li[**Uso común:** Es ideal para las primeras etapas del diseño, cuando se están explorando diferentes conceptos y se necesita validar la dirección general del proyecto] |

### Prototipo de alta fidelidad
Este tipo de prototipo es una versión más avanzada y detallada del producto final. Incluye algunas funciones básicas o limitadas, y se asemeja mucho más al producto terminado en términos de diseño y funcionalidad.

| Alta Fidelidad | Descripción |
| --- | --- |
| **Características** | :li[**Interactividad:** Permite a los usuarios interactuar con al prototipo, simulando la experiencia de uso del producto final] :li[**Detalles visuales:** Incluye elementos de diseño más refinados, como colores, tipografías y gráficos] :li[**Funcionalidades básicas:** Implementa algunas de las funciones clave del sistema, aunque de manera limitada] |
| **Ventajas** | :li[**Validación de diseño y funcionalidad:** Ayuda a identificar problemas de usabilidad y funcionalidad antes de la implementación completa] :li[**Retroalimentación precisa:** Proporciona una base más realista para obtener retroalimentación de los usuarios y las partes interesadas] :li[**Demostraciones:** Es útil para presentar el proyecto a clientes o inversores, mostrando un avance tangible del producto] :li[**Uso común:** Se utiliza en etapas posteriores del desarrollo, cuando se necesita probar y refinar aspectos específicos del diseño y la funcionalidad] |

## 3. Proceso de desarrollo del prototipo según requisitos
El desarrollo de un prototipo efectivo requiere seguir un enfoque estructurado que asegure que las funcionalidades y objetivos del proyecto se aborden adecuadamente. 

Este proceso se divide en las siguientes etapas clave:

| Etapas | Descripción |
| --- | --- |
| **Definición de los requerimientos** | :li[Identificar los requerimientos funcionales y no funcionales] :li[Consultar con los interesados] :li[Documentar los requerimientos] |
| **Análisis de sistemas críticos** | :li[Identificar los módulos o funciones críticas] :li[Determinar las dependencias y riesgos] :li[Priorizar los sistemas críticos] |
| **Diseño del prototipo** | :li[Prototipos de baja fidelidad] :li[Diagramas de arquitectura y flujo de datos] :li[Prototipos de alta fidelidad] |
| **Construcción del prototipo** | :li[Seleccionar herramientas y tecnologías] :li[Incorporar seguridad desde el inicio] :li[Crear versiones iterativas] |
| **Validación del prototipo** | :li[Pruebas de usuario] :li[Pruebas de funcionalidad] :li[Pruebas de seguridad inicial] :li[Recopilación de retroalimentación] |

## 4. Buenas prácticas OWASP en el desarrollo de prototipos
La *Open Web Application Security Project* (OWASP) es una referencia clave para garantizar la seguridad en el desarrollo de software.

| Buenas Prácticas | Descripción |
| --- | --- |
| **Actualización y mantenimiento** | :li[Utiliza bibliotecas y frameworks actualizados] :li[Monitorea vulnerabilidades conocidas en las dependencias del proyecto] |
| **Gestión de autenticación y sesiones** | :li[Usa contraseñas fuertes y hashing seguro (por ejemplo bcrypt)] :li[Implementa autenticación multifactor (MFA)] |
| **Manejo de errores** | :li[No reveles detalles del sistema en mensajes de error] :li[Registra errores de manera segura] |
| **Protección de datos sensibles** | :li[Usa cifrado (TLS) para datos en tránsito] :li[Evita almacenar datos sensibles innecesariamente] |
| **Validación de entrada** | :li[Asegúrate de validar todas las entradas del usuario para prevenir inyecciones de código (SQLi, XSS, etc.)] |
